# Time Management implementation plan

Priority: after the verified Family backup code gate, Time Management is the next Goals & Life Planning area. Tasks / Goals, Career and Travel remain sibling areas; preserve their data and navigation. This is the full product direction with staged acceptance, not a claim that all functions exist today.

## Product outcome and initial release
Help the user choose realistic work for today, reserve time for existing tasks and goals, focus, reschedule and review actual effort. Use four primary views: Today, Week, Focus, Review; task and goal selection opens a picker/detail view. The first coherent release includes real saved tasks, priorities and duration estimates, manual daily/weekly blocks with conflicts and capacity, goal references, a restart-safe focus session with breaks, and a planned-versus-recorded review. No fabricated productivity, salary-impact estimates or activity surveillance. Users control ordering and schedule changes. Recurring routines, optional reminders and calendar conflict integration follow on the same architecture, not separate task stores.

## Data and integration decisions
Keep TodoService/user_todos authoritative for personal tasks. Add optional validated estimatedMinutes, goalRef and explicit dueDate fields while preserving old fields and unknown legacy properties. Migrate the No Deadline sentinel on read without rewriting all tasks; invalid/ambiguous legacy dates remain visible for review. Family and career references are {domain, id, householdId?}; resolve display/status through read-only adapters. Missing/archived sources remain labelled and can be unlinked without deleting the original. Completion delegates to the owning service with an explicit user action; a completed focus timer never marks a task complete automatically.

Add one versioned encrypted planner document, proposed key finlife_time_planning_v1, with settings, blocks, routines, sessions and reminder registrations. Blocks reference tasks and contain id, localDate, start/end UTC instants, IANA zone and optional routine occurrence key; no duplicate task contents. Sessions contain stable id, taskRef, state, start/paused timestamps, elapsed segments and planned duration. Use serialized mutations, validate before persistence, inspect storage results, and commit visible state only after success. No private-to-Family cross-store transaction is implied; orphan references must fail visibly and be recoverable.

Store instants in UTC, preserve the block's IANA zone and date-only deadlines as local YYYY-MM-DD values. Use half-open [start,end) intervals so adjacent blocks do not conflict. Reject nonpositive duration and invalid dates. Day/week grouping uses the user's planning zone and chosen first weekday. Crossing midnight splits display/review by local day while retaining one session identity. DST gaps require an explicit valid replacement time and repeated clock times require a chosen offset; do not silently shift commitments. On device-zone changes offer keep-original-zone or adopt-new-zone; no automatic block rewrite. Timer display derives from persisted timestamps, not interval ticks; on restart/clock jumps ask the user to reconcile unobserved time rather than asserting continuous productive work.

## User journeys and acceptance gates
1. Foundation: safely read existing tasks; add/edit/complete through the same owner; load/save failure keeps the last confirmed data and draft with Retry. Criteria: concurrent writes retain both tasks, IDs unique, corrupt reads never seed/overwrite, failed writes do not return optimistic success, legacy fields preserved, duplicate retry guarded. Tests use fixture storage. Native task form failure/restart is a separate gate before claiming the complete journey.
2. Today/Week: select date, see unscheduled tasks, set priority and estimate, add/move/remove a block, see remaining available minutes and conflicts. Manual scheduling is first; optional suggested placement never commits automatically. Criteria: 7-day navigation; adjacent/non-overlapping/overlapping/overnight intervals; no duplicate task records; completed/source-missing visibility; over-capacity explicitly flagged; clean empty state and retry; state survives restart. Inspect Android interface and 320px/large-font layouts before this stage passes.
3. Goals: attach existing Family or saved Career goal to a personal task; show contributing tasks and time. Criteria: household isolation, no seeding Career mocks, deleted goal labelled, time does not alter pledge/savings amount, link survives restart, unsupported goal stores not offered as real data.
4. Focus/Review: start, pause, resume, stop/cancel; optional break; record actual time and compare with planned time by day/week and goal. Criteria: one active session, repeat taps idempotent, pause excluded, app suspension/restart/clock adjustment handled, cross-midnight segmentation exact, no automatic completion; clearly distinguish recorded focus from all actual work. Native background/reopen evidence required, not a mocked-timer claim.
5. Recurring routines: daily/selected weekdays, start/end dates, skip/move one occurrence or edit future series. Criteria: deterministic occurrence IDs, no duplicate generation on refresh/restart, DST tests, past completed history preserved; recurrence does not duplicate underlying task identity.
6. Reminders/calendar: ask permission only when enabled; planner works when denied/offline. Criteria: owned reminder IDs recreated after edits without duplicates, cancelled individually, permission revocation handled, private lock-screen text default, no stale source notifications; native delivery verification on supported builds required. Calendar read access optional; no event writes without user action. A busy calendar contributes conflicts, never purchases/travel booking/financial mutations.

## Cross-cutting quality and compatibility
Accessible 44dp controls, screen-reader labels and state, logical focus, keyboard-safe scrolling, text scaling, contrast and status text beyond color. No mocking activity history or shame-based procrastination labels. Offline reads/mutations are local; any future sync needs conflict/version rules first. Strict read failure never becomes an empty writable planner. Store minimal timestamps and user-entered notes; no app-usage monitoring or external upload. Export planner and canonical task data through both user-data export and the unified backup domain; version schema, reject partial/future payloads, preserve data for old backups and include rollback before calling planner storage durable. Account deletion must include its owner. Restoring should not recreate OS reminders until permission/state reconciliation.

Tests: pure intervals/date/recurrence/aggregation; repository failure/concurrency fixtures; adapter reference isolation; real UI journeys; restart/background/permission handling. Each stage records exact devices, tests and unresolved limits. Do not conflate fixture round-trip with native restore recovery. Initial release is complete only when stages 1–4 and export/restore integration pass; stages 5–6 remain visible planned enhancements. Career/Travel broader implementation follows Time Management priority.
