# Family backup and restore gate

Scope: add Family ownership coverage to the existing Node unified backup engine without restoring or deleting live records. Acceptance: all 15 snapshot collections and separate Life Events round-trip; older backups without Family preserve it; malformed/unsupported Family payloads reject before writes; Family-only targets are protected by EMPTY_ONLY; failures restore both storage owners and unrelated records remain intact.

Ownership inspection: services/dataExportCollection.js and services/compliance.js provide Settings user-data export. That includes the authoritative Family snapshot and decrypted Life Events; it is a different format from the unified backup envelope. No Settings restore integration with FinlifeV4BackupRestoreEngine was found. The unified engine imports node:crypto and is exercised by Node qualification suites; this change does not make it mobile-compatible or add a mobile restore flow. FamilyRepository owns version-2 encrypted snapshot (15 collections), migrating 14 legacy collection keys read-only; income is snapshot-only. FamilyLifeEventStore owns encrypted AsyncStorage key finlife_family_life_events_v1. Household selection is separate. Legacy files remain preserved; the snapshot supersedes them.

Repairs: services/backup/familyBackupDomain.js collects/validates these owners, migrates legacy records without writing, rejects missing/duplicate-id/unknown-collection/future-version structures, and captures Life Events ciphertext for exact rollback. Unified engine adds optional FAMILY schema 1 in its current envelope, checksum/count coverage, Family-only overwrite protection and restoration under the existing replace policy. Older envelopes without Family leave target Family untouched; declaring Family without a payload rejects. Save/delete failure results now throw instead of being reported as successful restoration. Settings export format is unchanged.

Verification: tests/test_family_backup.mjs passed 12 isolated integration cases against installed code. Existing R4 backup suite passed 41/41 in an isolated copy containing identical changed sources. Tests use in-memory storage and mocked native providers, actual Node envelope encryption. Cases include plaintext/encrypted round trips, old envelope compatibility, malformed payloads, snapshot-write failure, failure after Life Events write, original ciphertext/absence rollback, and read-only legacy collection migration. No real restore/delete, emulator operation, release or deployment.

Approval: automatic review rejected initial active installation twice. Changes were verified in a workspace copy first. User then explicitly approved installation of the two verified source files; installation succeeded. No rejection workaround was used.

Limits: not a native restore certification or full semantic validation of every nested domain entity. Cross-process crash recovery/transaction isolation and the engine's existing idempotency assumptions require separate review. Native Financial Coordination source-restoration recovery remains separate and unverified; its fixture check is not native evidence. Newer backups must be restored by a reader supporting FAMILY; older app versions are not certified to preserve that new domain. Persistent rollback-storage failure propagates an error rather than claiming rollback completed.
